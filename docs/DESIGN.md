# 游戏设计与关卡

当前版本为 0.9。各轮设计动机和实现依次记录于下。

## 核心机制

危险的脉冲也是机器的能源。接收器不消耗脉冲，玩家可以重排反射器，让脉冲循环经过多个设备。设备供电有期限；后续关卡还需要“同一颗脉冲重复经过”的循环验证，并要求关闭外部来源后离开。

设计重点是持续系统的启动、维护与通行，而不是仅将镜子转向终点。动作层提供危险和布置时机；观察模式允许暂停思考，但不能在暂停时移动或编辑设备。

每个发射器最多保有一颗在场脉冲，避免数量无限增长和粒子泛滥。脉冲撞墙或命中角色后，在线发射器才补发。观察模式的预计弹道基于当前布局，不考虑任何未执行的修改。

## 教学与递进

1. **借一道光**：理解伤害与供能是同一脉冲，学会搬运和旋转。
2. **两次转弯**：通过两面反射器绕过隔断。
3. **别让它结束**：固定大半回路，只补最后一角，发现循环。
4. **一光两用**：一颗脉冲同时维持多个负载，自行搭完整循环。
5. **慢半拍**：加入缓冲器，理解循环周期与供电期限。
6. **离网运行**：建立循环后关闭来源，验证系统独立运行。
7. **最后一班**：绕过隔墙建立凹形循环，维持三个设备并离网。

参考布局在 `src/levels.ts` 的 `solution` 字段，第三次提示显示轮廓；游戏不会自动替玩家放置。允许找到其他可行布局。参考布局可解由自动测试保证，但关卡是否有太简单的替代解，需要人工测试。

## 碰撞与时间

- 逻辑与渲染分离。模拟子步最大 1/120 秒，单次 step 最多处理 0.2 秒，避免后台恢复造成大步穿透。
- 脉冲方向限制在四个轴向，中心触发镜面转向；反射保留跨中心的偏移。
- 角色采用圆与轴对齐矩形接触；分轴更新允许沿墙滑动，长距离移动分步处理。
- 接收环以脉冲唯一编号验证重复访问；供电耗尽后清除验证。
- 游戏用时只累计运行中的模拟时间，观察与菜单暂停不计时。
- 受击保留布局，不回滚整个谜题，降低动作失败对思考的惩罚。

## 美术与声音

代码生成工业立体模型、地板、灯带、金属反射器、小机器人和接收环。灯光包含半球光、主方向光、冷色补光、软阴影、PMREM 预过滤的程序环境与可选 Bloom。景深使用深度 pass，按角色相机空间深度对焦，为正交相机适配深度转换；默认关闭，拍照时可以对比。反射与脉冲消失产生池化实例火花。

纸本文书使用深墨、暖纸和朱砂，运行仪表使用墨蓝底和亮色读数。标题与信文用宋体，操作用黑体，数字和键位单独排印。研究参考与布局规则见 `UI_DESIGN.md`。角色有五服色、三头饰、三胸章，模型与材质实时变化，只有外观差异。

《A Short Hike》用随地点变化的编曲标出空间，《Celeste》的作曲者刻意控制音乐的速度，给玩家计划下一步留出余地。《借火》的八套场景配乐使用同一组音程动机，改变拍号、音色与疏密。码头的簧音用六个八分音符标一小节，织盘的短木音只用五个。机房供电后加进答句，暂停观察时让乐句停下来，给读图留出安静。旋律由项目自行编写。[《A Short Hike》开发者访谈](https://blog.playstation.com/2021/08/05/crafting-a-tiny-open-world-a-look-behind-the-scenes-at-the-creation-of-a-short-hike/) · [《Celeste》团队访谈](https://www.gamedeveloper.com/game-platforms/road-to-the-igf-matt-makes-games-i-celeste-i-)

每个接收环得电、失电和拒收各有一种节奏，高优先级线路警报触发配乐短暂让位。反射声限频，避免闭环连续发声盖过设备变化。程序为翻页、梭轮、班表和邮戳分别合成声音，设备声与界面声接入不同的增益通道。总音量位于压缩器之后，设备、配乐、界面音量分别可调。关键现场声也可使用文字字幕。相机反馈是随时间衰减的渲染偏移，「相机震动」和「减少动态效果」均可关闭它。

存档有自动快照和三个独立手动槽，外观随手动槽恢复，设置与进度统一导入／导出。导入先校验再确认替换；旧存档补新字段的默认值。

此版仍需在真实浏览器观察 UI 遮挡、色彩、阴影和运动辨识度，不能把程序美术实现等同于完成了视觉验收。

## 后续优先级

1. 真实玩家试玩：是否无需讲解理解搬运、放置位置和循环验证。
2. 修复镜面拿取／放置、危险接近源头、观察模式的交互问题。
3. 为每关找捷径与重复解，强化“发现新关系”而不是重复摆四角。
4. 手柄菜单导航实测与不同设备适配。
5. 比较动作模式和更慢脉冲的辅助模式，避免操作门槛掩盖谜题。
6. 再考虑增加新机制，例如路由阀或消耗型负载；不要先增加装备、随机地图或大剧情。

## 第二轮：中继站（0.2）

新增五间机房，建立“装置承担多个角色”的关系：反射器既可以转向，也可以作为重量；脉冲携带身份、方向和冷暖属性穿越空间。光闸由压板占据关系实时决定，只阻挡脉冲，避免玩家被门夹住或永久困住。

| 机房 | 新的思考关系 |
|---|---|
| 留下一个人 | 自己踩住压板与让反射器替班；打开必经光闸 |
| 隔墙有耳 | 水平隔墙与单一实体通道迫使光路利用导光井，保持入井方向 |
| 冷暖之间 | 同一脉冲依次变冷、变暖，满足不同接收器 |
| 无人值守 | 用额外反射器维持压板，再闭合跨空间光路 |
| 把夜晚折起来 | 压板、空间折叠、两次换相、多负载和离网同时成立 |

新章节自由选关，提供机制教学和逐步提示。撤销在每次有效拿放、旋转、源开关操作前记录完整快照，最多 64 步；不只退回镜子，还恢复当时的脉冲、供电与开关。重进和读档清空历史，提示使用记录不因撤销而清除。

场景有铸造间、温室、档案库三种外围装饰与新章节地板配色。新增压板下压、光闸光幕、成对编号的旋转导光井、双色换相器、冷暖接收环形状标记、区域色光与低密度尘埃。装饰放在边缘，不改变碰撞地图。

现阶段仍需试玩观察替代解、动作等待和教学理解。测试保证参考布局可达且可解，不代表关卡只能有唯一答案，也不能自动判断趣味性或美术质量。


## 第三轮参考与实现（0.4）

阅读了 [Arvi Teikari 的规则系统分享](https://www.gdcvault.com/play/1026628/Reading-the-Rules-of-Baba)、[Kim Swift 的 Portal 开发复盘](https://www.gamedeveloper.com/design/thinking-with-portals-creating-valve-s-new-ip)，以及 [Airborn 的 Ori 美术制作介绍](https://airborn-studios.com/projects/ori/)。前两者启发我们关注规则组合和单概念教学，后者强调分层空间、可读性及画面为玩法服务。下述设计是本项目据此做出的选择，没有复用它们的规则文本、人物或视觉素材。

新增能力是记录位置而非复制整个人：投影占据压板，但不拿镜子、不反射、不受击、不改变开关。最多两段、每段六秒，带来位置、资源与时间三个约束。双锁要求同时满足，反向闸要求空闲，巡逻因此产生时序意义。路径循环时跳回起点，控制界面明确说明这一点。操作与自动结束不会创建无限投影，所有轨迹有采样和持久化上限。

四关分别教授静止示教、双点并行、互锁时序和混合系统。第三关的静止投影无法通过两道闸，必须录下离开动作；最后一关把双点签收与旧导光井、冷暖回路和离网验证结合。自由选关方便比较机制与收集试玩反馈。

视觉将可玩平面放到一栋实际屋顶上，分成近景建筑／植被、关卡设备、温室结构和远景城市，使用曲线构件、角色剪影、少量区域灯和动态雨线形成层次。装饰均在碰撞地图外，不改变可达性。雨幕是视觉粒子、围巾是运动动画，不将它们申报成流体或软体仿真。

代码验证不等于试玩。下一步评估应观察玩家能否不经口头解释理解 F／G、双锁与反向闸，是否看得清压力板和光幕，以及时序关的等待是否过长。记录具体困惑点再修改，不能因为参考解通过就认定已有商业游戏的深度或美术完成度。


## 第四轮：可试验的动态回路（0.5）

复查了 [Awaria 作者介绍](https://vanripper.itch.io/awaria)、[Portal 开发复盘](https://www.gamedeveloper.com/design/thinking-with-portals-creating-valve-s-new-ip)、[Ori 美术团队的制作说明](https://airborn-studios.com/projects/ori/) 与 [Slay the Spire 设计迭代分享](https://www.gdcvault.com/play/1025731)。参考的重点是让规则产生可理解的结果、降低试验成本、用可观察反馈迭代；没有复用其素材或关卡。

本轮不增加关卡数量，在“留下一个人”和“无人值守”加入接收环供电接管：闸门的压板条件与指定接收环供电条件做 OR。人可以先压板启动，接收环亮起后接管；断电后需要重新启动。原有重物解依然有效，新的单镜／少设备解需要理解时间与状态，而非只把镜子摆成一个图案。

未来推演使用当前快照复制 Simulation，按 1/120 秒演算十二秒，每 1/8 秒采样。它包含当前真实无敌时间、角色原地受击、回声、录制、冷暖、缓冲、传送、供电过期与光闸逻辑，记录事件并可回放。所有计算在副本内完成，不能获得星级、推进实际时间、修改布局或存档。角色不移动，是界面明确说明的假设；它不猜测玩家未来操作，也不是自动求解器。

T/V 临时试验点保存完整快照，恢复清空操作撤销栈，防止跨越两份分叉历史。试验点不随存档持久化，换关／重试／读档清空，不回滚剧情或提示记录。

增加定位反馈事件：错误相位、供电超时、脉冲丢失。视觉增加青绿色接管线、按区域分化的花冠／铜管风机／柜列。温室花冠随供电展开，场景提供维修结果的可见反馈。仍需要人工检验可读性、构图、性能和节奏，未将这些新增代码当作已经完成的视觉验收。

## 第五轮：时间也可以编排（0.6）

回声不再只提供录制与删除。调度器把原有位置示教延伸为可调整的时间表：单段相位前后移动，周期在 0.5–6 秒之间缩放，支持同步归零；无脉冲且来源在线时，同步也启动发射。路线图明确画出循环跳回，时间条标注对各示教板的占据窗口。全部修改通过原有历史快照撤销、保存；调度界面暂停模拟，避免修改时系统偷偷推进。

新增两张可自由进入的练习单，保留原有主线和花园结尾：

| 工单 | 设计目标 | 防止只用静态钥匙的约束 |
|---|---|---|
| 一个人的接力 | 单段回声依次启动两个岗位，供电后接管 | 两块投影专用板只给一个回声名额 |
| 每一圈都要交班 | 回声周期匹配整圈光路，随后离网 | 两道闸每圈都要分别放行；错误周期会累积漂移 |

第十八关的参考周期约 5.714 秒。参考解测试通过正常搬运、实际走位录制、周期调整与同步启动建立；额外的隔离模拟检查正常周期能在关源后维持九十秒，而错误周期会逐圈失约。这里的固定循环是教学情境，不是所有布局都需要同一个周期。

可选挑战与星级分开保存，鼓励不同次维修探索不同目标：“一颗就够”要求整局只借一颗光、无丢失无受击；接管关的“亲手启动”要求完工时没有反射器压板；“经得起等待”要求全部设备连续保持循环验证十二秒。它们既不阻止通关，也不增加课程评分宣称。

静态矩形审计发现第五关原有两个绕过缓冲器的持续解，新增两根维修柱后，在同样枚举范围内只剩一个可持续候选，且经过缓冲器。保留其他关多解，避免将参考布局做成坐标密码。审计有明确边界，不将导光井的非矩形线路或六镜凹形线路的零结果解释成无解。

美术反馈增加暖／冷色流式光尾、接收环外圈电量刻度与内圈验证标记、可弯曲的分段围巾，以及与角色轮廓一致的工装投影。传送处光尾断开，倒放推演时清理旧尾迹；减少动态效果可关闭光尾。界面保持原有系统中文字体，工具条根据说明文本高度自动下移。

渲染优化使用原生实例化合批：地面静态盒体、远景建筑、随风叶片与花冠花瓣共用几何／材质；动画父组和独立状态的设备保留。仅远景盒体在三个主题中分别减少 182–234 个提交对象，不把这一结构结果写成实测帧率。撤销和试验点恢复只重建运行对象，不再重建屋顶与城市。回声插值改为二分定位；HUD 时间条复用 DOM，避免每次更新都重建整棵状态树。

## 第六轮：光的状态决定路线（0.7）

本轮参考的是创作者资料中的具体做法，而不是复用游戏资产或剧情：

- [Valve：Integrating Narrative and Design — A Portal Post-Mortem](https://cdn.akamai.steamstatic.com/apps/valve/2008/GDC2008_PortalPostMortem.pdf)：讨论叙事与玩家行动之间的距离、让环境表达故事，以及通过观察试玩迭代。本项目据此让补光、远端接管和交班成为明确的关卡任务，并保留低压力的单装置入门。
- [Airborn：Ori 的美术制作](https://www.airborn-studios.com/projects/ori/)：介绍先测试玩法灰盒再制作美术，以及有层次、保持可读性并服务玩法的画面。本项目据此在棋盘后方加入玻璃植物装饰，避免把装饰放进可走区域；双色材质、反射斜面和路径使用一致的颜色语言。
- [Awaria 作者介绍](https://vanripper.itch.io/awaria)：维修、零件交付与躲避危险组成行动目标；[Helltaker 作者介绍](https://vanripper.itch.io/helltaker)也保留跳过谜题的入口。本项目继续提供自由选关、分步提示与观察，不将强制操作压力作为内容深度的替代。
- [Arvi Teikari：Reading the Rules of Baba Is You](https://www.gdcvault.com/play/1026628/Reading-the-Rules-of-Baba)：该演讲主要讨论规则的程序表达和迭代。下面“由少数规则组合产生线路变化”是本项目自己的设计推演，不声称是演讲中的具体关卡建议。

双色棱镜是一种可搬运／旋转的反射器。暖光沿标记的暖色斜面反射，冷光沿相反斜面反射；Q 旋转会交换两者。它保留脉冲编号和颜色，不分裂脉冲、不消耗能量、不自行改变状态。换相器把颜色带回棱镜，使同一格在不同次经过时承担不同的路由角色。

新章节共四关：单活动棱镜连接上下支路；两种来向构成四次回应的蝴蝶回路；跨区导光井与先值守后接管组合；最后将双支路与周期回声值守结合。第十九关先给出大部分固定件，避免同时教学搬运、完整搭图和双色规则。其余关逐步撤去固定布局，复用已学能力。第二十一关的搬运测试发现放下镜子会封住人所在的通道，现已给实体维护通道留出侧向出口。

观察预览从暖光来源出发，使用位置、方向和颜色共同检测循环；若只按位置和方向去重，会提前截断双色路线。预览同时报告墙体、关闭光闸、边界、闭环或步数上限。传送保持断线。动态时序依然由隔离的十二秒推演解释，静态预览不承诺投影未来的占据状态。

可读性改进包括实际交互对象的地面标记、双色棱镜的交叉透明斜面和独立状态灯、按冷暖着色的观察路径，以及 Tab 俯视视角。俯视下相机向上方向为世界 -Z，移动同步切到该坐标；立体下保留原有镜头相对移动。选关册按五个章节组织，使用开工状态生成缩略图，不泄露参考解。

分光温室的玻璃植物悬饰采用共用平面、线框与金属圆环，随供电柔和增亮，减少动态模式下归位；主色对应棱镜的冷暖材料。新装饰位于可玩区域后方，不修改碰撞数据。画面仍需在真实浏览器复核，不把几何测试或程序化建模等同于美术质量验收。

## 天亮之前 · 七区复网（0.9）

把一次长线首通定义为拿到回水塔的总图。八区各有六个供电地段，每个地段验收配线、调船、现场轴座三项。48 张织盘、48 份航表、48 处三维联检都计入结局。前一区复原三段即可推进；炉渣巷与风篷市场为双孔桥供电，雨尺船坞与盐风苗圃为刻字坡供电。玩家能换一条支线继续，地图按实际交接进度改变。已完成的老关、返修成绩、挂机和重复签收均不计入新战役内容预算。

### 三种推理

- 从《Baba Is You》中可以操作规则本身的设计，演绎出织盘的供电离合。改变路由还会改变某只梭轮是否能转动。中间测孔、绝缘、齿带及反齿逐步出现。发布的是固定题库，每盘按玩家实际所处状态寻找合法提示，符合条件的接法都能签收。[Hempuli 的游戏介绍](https://store.steampowered.com/app/736260/Baba_Is_You/)
- 《Into the Breach》提前公开攻击意图。航表采用相同的可读性原则。玩家能提前看到整圈的占闸、船尾、潮窗、逆向航行和两船交接，并逐拍定位冲突。后期还须协调半圈补班和允许同向合闸的船队。签收航表后，同一地段的现场联检图会收到过道放行表，用真实模拟比较两种出发时机。[Subset Games 游戏介绍](https://subsetgames.com/itb.html)
- 《The Witness》的作者在介绍中强调各地点的谜题提供新想法。这里给三维维修增加同一布局接受多组入口测试的规则。甲路的实际供电与乙、丙等校线的边界方向、出口和相位可以分别正确或失败。通过配线工序可获得现场轴座的假设试转校样，玩家可以先去现场查问题，再回到桌前取得工具。[Thekla 的游戏介绍](https://store.steampowered.com/app/210970/The_Witness/)

街区使用原创线路图、八幅带停机与复网两种姿态的地标版画和街道物件交班记录。游戏本体包含固定题面、逐题可解性测试、艺术与文字，离线文件可直接运行。

### 首通时长校准

目标是让初次接触规则的玩家自然完成十小时以上的有效游玩。设计按八区阶梯预算 33、42、60、78、96、108、126、144 分钟，合计 687 分钟。没有计时锁，了解解法或持续使用提示的人可能显著快于预算。将预算整体缩短 20% 后约 550 分钟。程序求解器验证各工单可完成和最少操作数，不能测量真人推理时间。

首次试玩者可从新存档进入，照常选路和使用提示，完成或中止时在值班簿导出 CSV。每人保留一份最终记录；不要混入已知解的开发者跑图。用以下命令对照最快、居中、最慢的完整首通和达到十小时的人数，并查看中途停止的位置、使用提示情况及各工种/街区的实测时间。用偏短区段和高放弃率定位下一轮关卡改进。

```sh
npm run audit:campaign
npm run audit:campaign -- 第一位试玩.csv 第二位试玩.csv
```

桌面调盘、现场和联检图在前台累计时间，暂停、后台和长时间无操作停止计数。地图、来信阅读和重玩另行游览。超过两分钟完全不动的思考可能少计，短时离座可能多计。所有数据留在本地。


### 退信寻址

这条支线让交班笔记参与推理。修好有关地段，玩家就能把实地见闻与一封地址破损的退信摆在一起读。分别选好寄件地、收件地后可以对调印章或试投。正确投递会显示去向、居民回信和对应邮戳。八封独立投递，主战役的任何工单都不以投递为先决条件。邮袋单独记录解读未投邮件的前台时间，战役 CSV 只统计复网工单。
