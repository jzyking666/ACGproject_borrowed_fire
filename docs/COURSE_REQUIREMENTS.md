# 课程要求对照：Topic 2 / Interactive Game

依据工作区 `ACG_Project_Announcement.pdf` 第 1–4 页。分值是公告候选分值，最终由课程教师认定。目标是完成基础要求，并准备个人选做上限所需的 15 分。

## 基础要求

| 要求 | 当前实现 | 演示方式 |
|---|---|---|
| 场景、几何、纹理与材质 | `view.ts`：工业机房、机器人、反射器、接收环、移动门；程序生成拉丝金属／划痕／维护标记纹理；金属、发光、粗糙度材质 | 转动相机查看几何、纹理与材质差异 |
| 动画 | 转身、步行手臂、搬运、脉冲与缓冲、接收环转子、出口开合 | 移动、搬运、恢复供电 |
| 主角控制 | `engine.ts`、`main.ts`：移动、精细移动、交互、旋转、开关 | 键鼠操作并解释相机相对移动 |
| 相机控制 | 正交三维相机、旋转、缩放、复位 | 右键拖动、滚轮、C、手柄右摇杆 |
| 开始与结束界面 | 主菜单、每关结算、最终夜班结束、重试与返回 | 完成机房，展示结算 |
| 完整可玩 | 十二关、解锁、受击恢复、重试、提示、观察、暂停、记录 | 全流程人工验收；逻辑测试验证十二关可搭建参考解并通关 |
| 用户说明 | README、游戏内操作指南、教学和工单 | 不依赖开发者讲解上手 |
| 工具限制 | Three.js 图形库；自写模拟、交互与流程 | 无 Unity／UE5 或可视化编程引擎 |

## 个人选做主路线：5 × 3 = 15 分候选

| 项目 | 公告分值 | 实现范围与代码 | 直接演示 |
|---|---:|---|---|
| 碰撞处理 | 3 | `engine.ts`：圆与 AABB、分轴滑动、移动细分、脉冲与镜面／墙体／角色碰撞、受击恢复 | 贴墙移动、反射与受击；解释子步与反射公式 |
| 存档与读档 | 3 | `storage.ts`、`main.ts`：自动断点、3 个独立手动槽、读取删除、文件迁移、旧格式兼容；完整保存运动脉冲、手持物、设备供电及外观 | 持物／脉冲运行时 J 保存，改变布局后读取，刷新继续，再导出 JSON |
| 多控制器 | 3 | `controller.ts`：键鼠 + standard mapping Gamepad API；摇杆死区、按钮边沿、断连复位、菜单重复导航 | 实体手柄移动、拿放、旋转、观察、暂停、菜单与相机 |
| 辅助界面 | 3 | 工单与历史成绩、关卡选择、设置与操作指南、存档管理、分步提示、观察弹道、设备编号 | I 查工单，J 存档，设置文字大小；区别于开始／结束基础 UI |
| 自定义外观 | 3 | `appearance.ts`、`view.ts`：5 服色 × 3 头饰 × 3 胸章；实时三维预览、持久化与存档恢复；头饰和胸章为不同几何 | “维修员”修改三类外观，进入机房／刷新检验 |

这五项用于覆盖选做上限，不依赖提高关卡难度或先发布网站。手柄需要真实硬件验证；各项工作量和辅助界面认定仍需答辩前与 TA 核对。

## 验收边界与成绩

- 无实时路径追踪、流体、软体、骨骼蒙皮或在线多人。个人选做选择子集，不要求实现公告所有可选技术。
- 环境与景深使用 Three.js 模块；报告应说明库的贡献与本项目的集成、正交深度适配、对焦和交互部分。
- 71 项逻辑测试、类型检查与生产构建在本机通过。14 项浏览器测试已编写并检查可发现，未在本机执行。实体手柄、画面与完整游玩待实机验收，见 `VALIDATION.md`。
- 功能清单不能保证满分或精选展示加分。

单人基础对应口头报告基础 10 分，选做最多 15 分，即口头部分候选 25 分；另有期中报告 5 分、最终个人报告 10 分。总分公式为 `S = M + k (O + W) + B`。需要理解代码、记录实际贡献并准备独立报告和问答。课堂加分以入选与课程展示规则为准；日期及演示步骤见 `SUBMISSION.md`。
