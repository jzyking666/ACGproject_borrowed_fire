使用 macOS 系统 WebKit 从本地文件打开游戏，按实际交互进入首页、控制手册、存档、衣帽柜、章节、通讯、地图、寻址、调度、现场、推演、拍照、暂停等页面。1280×720 检查了 32 个画面状态，签收回执、终章、收到的回信、删除确认和经典结算使用独立测试进度。又在 800×600 进入设置打开 120% 字号，复查查表、文书、工具和操作按钮。两种尺寸的检查均未发现整页横向溢出或对话框页脚超出视口。

## 单文件离线导出

`npm run build:html` 类型检查后使用已有 Vite 将游戏编译为单个 IIFE，把 JavaScript、CSS 和 Three.js 许可内嵌至 `release/borrowed-fire.html`。不安装额外依赖，不修改普通网站构建配置，也不覆盖 `dist/`。

导出器要求恰好一个脚本和一个样式输出，拒绝未内嵌的额外素材与外部样式资源，校验脚本可以作为经典 JavaScript 解析，并转义内嵌脚本／样式结束标签。

新增离线浏览器回归：将唯一 HTML 复制到带中文与空格的临时路径，断网后从 file URL 启动，检查剧情、移动、存档刷新以及无外部资源请求。本机尚未安装测试浏览器，此用例未在本机执行。

file URL 的本地存储行为依浏览器而异；存档导出／导入可用于在离线版和网页版本之间迁移。分享时发送构建后的 HTML，收件人无需 Node.js；仍需支持 WebGL 2 的桌面浏览器。

## 返修委托与变帧长光路（0.8）

- 五封报修单各验证未维修时连续 60 秒仍保留报修现象且出生点安全。随后使用真实移动、装置动作、光闸、示教与受击判定，各完成一次预算内无伤交付。另有超预算签收和同单替代方案。
- 实测旧实现的 03 号正确回路在 90 Hz 模拟帧下运行 60 秒会丢失 24 颗光。在不均匀子步中，原来的器件中心距离阈值可能漏掉实际经过。现在检测本步运动线段是否越过格心，保留反射、传送和缓冲释放的剩余时间。七套完整回路分别以 60、90、120、144 Hz 及两组抖动输入对照运行超过 77 秒，检查事件流、位置与等待时间。另测动态光闸、修正前的快照和缓冲释放。
- 纸面试转检查首个分歧、未被照到的镜、封闭光闸、固定件、传送断线、冷暖拒收。动态诊断核对原地受击、闭闸、墙体、越界、供电到期与观察窗内漏接设备，并验证时间轴定位。
